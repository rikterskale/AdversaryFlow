# Repository review — October 1, 2026

The repository review found and corrected failures in input validation, receipt
handling, scope enforcement, runner input, and browser recovery. The final local
checks pass. The corrections and this report are committed together on top of
`4fc5125` following the request to commit and push to main. Validation was
completed before committing; no release was published.

These results support confidence in the tested behavior. They do not establish
100% certainty, exhaustive path coverage, or successful execution of every
catalog command on every possible target host.

## Scope and method

The review covered the service/API, ATT&CK indexing and cache, catalog and safety
metadata, intelligence imports, signed content packs, Atomic export, engagement
persistence and audit records, webhook delivery, telemetry correlation, generated
operator runners, report generation, browser planning/evidence/export flows,
launchers, Docker deployment, schemas, dependency locks, packaging, and CI.

The initial tracked inventory contained 194 files, including 32 backend Python
files, 12 schemas, five maintenance/release scripts, and ten GitHub configuration
files. The final frontend source tree contains 48 files, including tests and
styles. Generated frontend assets were rebuilt and checked inside both Python
distribution formats. Dependencies and local caches were treated separately
from application source.

Validation combined source review, lint/type checks, existing behavioral tests,
new failure-path regressions, actual browser/service integration, harmless
operator-runner fixtures, an isolated wheel installation, and a fresh Docker
deployment. Catalog commands were checked as data and for POSIX shell syntax;
the full catalog was not executed on the user's workstation.

## Corrected findings

| Priority | Trigger and prior behavior | Correction |
| --- | --- | --- |
| P1 | A loopback service accepted an arbitrary HTTP Host, allowing a hostile hostname to reach local session/API routes through DNS rebinding. | Local mode accepts localhost and loopback Host values. Explicit remote mode retains bearer-token enforcement. |
| P1 | Signed Atomic content could enable a step explicitly withheld in the submitted reviewed plan. | Atomic export preserves the original withheld decision, including repeated technique occurrences. |
| P1 | A raw receipt could disagree with execution results; repeating a technique in another tactic hid an earlier disagreement. | Every matching execution occurrence must agree with the receipt's outcome, timestamps, exit code, cleanup state, run identity, and digest. |
| P2 | Browser plan imports coerced array-shaped enum fields into apparently valid strings, then failed during rendering. | Command risk/interpreter, execution outcome, and scope-platform imports require their correct types. |
| P2 | Array/object schema or procedure-source values could raise unhandled backend exceptions. | Invalid enum shapes produce validation errors before processing. |
| P2 | Malformed execution records reached persistence/export; non-finite numbers and invalid Unicode could fail during serialization. | Execution fields, bounds, timestamps, hashes, references, finite JSON, and UTF-8 are validated. |
| P2 | Non-ASCII bearer/CSRF headers raised an exception in string constant-time comparison. | Comparisons use UTF-8 bytes and return the appropriate authentication/CSRF response. |
| P2 | Invalid Unicode or a non-string STIX reference source could crash structured intelligence imports. | Imports reject invalid text and require string reference sources. |
| P2 | A signed ability could pair a Windows executor with Linux/macOS, or Bash with Windows. | Signed ability validation enforces executor/platform compatibility. |
| P2 | A non-ASCII manifest digest could crash signed-pack verification. | Manifest payload digests must be valid lowercase SHA-256 strings before comparison. |
| P2 | Atomic backlog persistence failure returned an opaque server error after generating the archive. | Store failures return an actionable HTTP 503. |
| P2 | Revoked relationships contributed mappings, and revoked techniques inflated gallery counts. | Revoked/deprecated relationships are excluded; counts match active actor techniques. |
| P2 | Closed runner input could endlessly repeat an assessment/cleanup or edit-reason prompt. | Bash and PowerShell abort cleanly on EOF, preserve completed-step evidence, and leave missing detection assessment unassessed. |
| P2 | Receipts belonging to techniques removed from scope remained in an export and caused server rejection. | Only receipts bound to the current exported scope are included. |
| P2 | Editing receipt-derived results retained a stale verified flag and raw receipt. | Editing receipt-bound fields clears verification and the raw payload; notes and independent detection assessment can still be edited. |
| P2 | Browser verification rejected valid Python receipts containing non-ASCII text; imported raw plan receipts were not cryptographically rechecked. | Browser verification handles Python schema 1.0 escaping and checks imported receipt digests before loading the plan. |
| P2 | Telemetry entry erased trailing newlines while typing; output hash fields could display values from an earlier evidence snapshot. | Editors preserve typing text and synchronize hashes when evidence changes. |
| P2 | An unexpected interface failure offered only reload, which could repeat indefinitely with a corrupt saved workspace. | Recovery offers a raw browser-workspace download; reset becomes available after requesting that copy. |
| P2 | A malformed HTTPS URL could crash report generation. | Malformed report links are omitted safely. |
| P2 | Skipped techniques were displayed as having run in the coverage matrix. | Skipped and executed statuses are distinct. |
| P3 | macOS runner messages described withheld steps as unsupported on Linux. | Messages use the actual selected platform. |

## Limits and remaining validation

- The one remaining Python skip is the POSIX executable-stub installer test,
  which excludes Windows. Native Windows interpreter checks did run.
- Native macOS/Safari, Linux-native launcher installation, and the full
  Python-version/OS CI matrix were not rerun locally for these changes.
  WebKit on Windows and Git Bash are useful checks but do not replace those hosts.
- The workflow matrix uses the recorded official cached bundles. It does not
  certify future upstream data revisions. The fresh Docker smoke independently
  verifies startup with an empty cache.
- Every catalog command depends on the lab host's utilities, privileges,
  policies, and instrumentation. This review executes harmless fixtures and
  bounded exercises, not all state-changing catalog actions or real targets.
- Receipts protect self-reported content integrity; they are not independent
  proof of endpoint execution or SIEM detection. Actual sensor integrations,
  reviewer-owned signed packs, and a user's external webhook destination need
  validation in the intended deployment.
- No exhaustive branch-coverage percentage or guarantee of zero future friction
  is claimed. The dependency audits describe the advisories available at review
  time, and do not prove the absence of undisclosed vulnerabilities.

Local evidence is retained under `.audit-cache/code-analysis/`: the final Python,
frontend, browser, crypto, Docker, packaging, and audit logs plus
`review-matrix.json`. This directory is ignored by Git. The prior dated review is
available in [CODE_ANALYSIS.md](CODE_ANALYSIS.md).
